## 新增：各账户现金余额 备份/恢复（驱动持仓市值占比进度条）
- 痛点：现金余额存在 `panorama_account_cash`（localStorage），原备份 payload 没带，恢复到手机后现金归零、占比进度条消失。
- `BackupActions.vue`：`buildBackupPayload` 增 `panoramaAccountCash: getPanoramaAccountCash()`（本地/云共用同一函数，一处加即两路都覆盖）；`applyBackupData` 增 `if (jsonData.panoramaAccountCash && typeof==='object') savePanoramaAccountCash(jsonData.panoramaAccountCash)`（老备份无此字段则跳过，不清空现有现金）。遵循「字段是否存在」判定，不靠版本号。
- 同步刷新：首页是 keep-alive，恢复后不会重挂载。`applyBackupData` 末尾 `window.dispatchEvent(new Event('backup-restored'))`；`Home.vue` 监听该事件 + `onActivated` 时都 `refreshMobileAccountCash()` 重新读 `getPanoramaAccountCash()`，保证占比进度条用恢复后最新现金。
- 导入：`BackupActions` 增 import `getPanoramaAccountCash, savePanoramaAccountCash`；`Home` 已有 `getPanoramaAccountCash`。

## 排查：手机云恢复后现金仍 0
- 现象：用户在手机端「云恢复」后各账户现金还是 0。
- 排查结论（代码无 bug）：`gist.ts` 对备份 JSON 原样存取不丢字段；`applyBackupData` 在 `panoramaAccountCash` 存在且为 object 时才 `savePanoramaAccountCash`（缺失则跳过，不覆盖现有现金）；大屏 `PanoramaDashboard.vue:366` 现金编辑确实持久化到 `panorama_account_cash`。
- 真正原因（二选一或叠加）：① 云备份 Gist 是在「加 `panoramaAccountCash` 字段」之前上传的，备份里根本没有该字段 → 恢复自然是 0；② 备份是从「现金从未设置过」的设备（手机，现金只能在大屏编辑）做的，会把云端覆盖成现金=0；③ 手机端跑的是改动前的旧构建，`applyBackupData` 无现金分支。
- 修复步骤（告诉用户）：在大屏（已录入现金、且跑最新代码）重新「云备份」→ 再在手机（同样跑最新代码）「云恢复」。切勿在手机端做云备份（会覆盖成 0）。若手机是独立构建/部署的 App，需先 rebuild/redeploy 再恢复。
