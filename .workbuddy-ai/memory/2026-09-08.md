### 修 bug：第四列右边被切出屏幕

现象：最右一列（交易记录/AI分析）右边界看不到。
原因：4 列的 `flexBasis` 百分比之和恒为 100%，中间还夹着 3 条 12px 的 `.col-resizer`，
总宽 = 100% + 36px；而 `.main-grid` 是 `overflow:hidden`，多出的 36px 表现为最后一列被裁掉。
（3 列时代就有 24px 溢出，只是不明显，加第 4 列后暴露。）

修法：新增 `colStyle(i)` 统一生成列样式，`flexBasis: calc(${w}% - 9px)`，
9 = `RESIZER_WIDTH * (COL_COUNT - 1) / COL_COUNT`，把 36px 平分到 4 列，总宽回到 100%。
> 以后改列数 / 改 `.col-resizer` 的 flex-basis，必须同步 `RESIZER_WIDTH`，注释已写在 CSS 里。

顺带修了拖拽手感：`handleDragMove` 原来用 `grid.clientWidth`（含 padding）算百分比，
改为减掉左右 padding 后的内容宽度。

## K线全景沪深300对比线最终还是没画出来——找到了真正的根因

上一节把颜色和数据去重都改了，用户反馈"确实还是显示不出来"，连星标K线独立页也不显示。
去重逻辑、retry 都没问题（Node + VM 模拟串行脚本注入跑通，6 个并发都能拿到 400 条），
截图也确认基金红线在画——但 0 个黄色像素。

**真凶：Vue 3 Boolean 类型 prop 的默认值陷阱。**

`MiniKLineChart` 原本是：
```ts
const props = defineProps<{
  ...
  showHS300?: boolean
  ...}>()
```
父层（StarKLinePanel / StarKLine.vue）从来没人传 `:show-hs300`。
Vue 3 编译器把 `showHS300?: boolean` 编成 `{ type: Boolean, required: false }`（**没有 default**），
此时未传入的 Boolean prop 解析为 **`false`**（不是 `undefined`），
于是 `props.showHS300 !== false && hs300Data.value.length > 0` 永远为 `false`，
对比线整条不画。

`git show HEAD` 验证 `props.showHS300 !== false` 这行早就在，所以这是**长期潜伏的旧 bug**，
不是本次重构引入的；用户说"最开始搞得时候能显示"应该是记错了（或者记的是 Detail 页 OKXChart，
那是另一个 `ref(true)`，不受这个 prop 控制）。

**修法**（`MiniKLineChart.vue:21`）：改用 `withDefaults` 显式给默认值：
```ts
const props = withDefaults(defineProps<{
  ...
  showHS300?: boolean
  ...}>(), { showHS300: true })
```
需要在 `import { withDefaults }` 引入。修复后截图：每个小图 ~440 纯黄像素 + ~1000 抗锯齿黄像素。

**踩坑教训（已写进 ~/.workbuddy-ai/MEMORY.md）**：
凡是用 `prop?: boolean` + 运行时检查 `prop !== false` 想做「默认 true、显式 false 才关」，
**必须 `withDefaults` 给 true**；不加就默认 false，逻辑全反。

## 全景大屏 K线列改成按账户排序（与左侧持仓列同口径）

**问题**：StarKLinePanel 之前直接 `getStarredFunds()` 用星标添加顺序渲染，
支付宝/腾讯/京东 的基金穿插在一起，看不出哪只属于哪个账户。

**修法**（`StarKLinePanel.vue`）：
- 新增 `ACCOUNT_RANK = { ali:0, TX:1, JD:2, observe:4 }`，`RANK_OTHER=3`
  （按 `source` 取账户权重，未匹配归「其他」）。
- `sortStarredByAccount(codes)`：先按账户权重升序，组内按 `parseFloat(todayChange)` 降序，
  完全复用左侧 `PanoramaDashboard.vue` 的 `buildAccountFunds + sortByChange` 同口径。
  涨幅相同则兜底用原星标顺序（稳定排序）。
- `refreshList()` 改成走新排序；`boot()` / `onActivated` 必须在 `ensureHoldings()` 之后再
  `refreshList()` 一次 —— 首次进入时 holdings 还没加载完，按 source 排会全跑到「其他」组。
- 加 `watch(orderSignature)`：持仓里任意基金 `source` 改了或 `todayChange` 变了，就重排，
  保持左右两列实时对齐。指纹只取 `code:source:todayChange` 三字段，避免无谓触发。

**验证**：用 `__vueParentComponent.setupState.starredList` 在页面里读排序结果，
6 只基金（2 ali / 2 TX / 2 JD，星标故意穿插 JD-ali-TX-ali-JD-TX）渲染出来是
`ali ali TX TX JD JD`，组内按真实今日涨幅降序（左侧同源）。

> 顺便：`observe` 排最后是因为左侧「持仓」列里就没有量化观察（它在第 3 列单独成块）。
> 用户没指定，但语义上对齐。
