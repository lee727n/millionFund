## 全景大屏「交易状态」边界二次修复
- 昨日修了 reactivity（computed 用裸 new Date() 被缓存）。今天用户反馈 11:04 仍显示「午休」。
- 根因：原 `tradingStatus` 只按 `getHours()` 判断，`h>=11 && h<13` 让 11:00-11:29 也归为午休；真实 A 股午休是 11:30-13:00。所以 11:04 误显午休，看着「没跟时间联动」。

## vConsole 开关翻车修复 + 星标K线空白修复（第二轮）
- vConsole 开关显示「面板加载失败」但面板其实在：根因是 Home.vue 之前 `import('vconsole')` 动态 new 了**第二个**实例，而 index.html 已通过 CDN 全局引入并（原）自动 `new window.VConsole()`——VConsole 是单例，重复 new 抛 "already exists"，被 catch 成「加载失败」，但原有的 CDN 实例仍在显示。
  - 修复：index.html 去掉自动 `new window.VConsole()`（只保留 CDN `<script>` 定义全局 `window.VConsole`，默认隐藏）；Home.vue 开关改为直接 `new (window).VConsole()` / `.destroy()` 控制现有全局实例，不再自己建实例。
  - 清理：`npm uninstall vconsole --legacy-peer-deps`（之前误装的 npm 依赖，现用 CDN 全局，未 import，包体无影响）。package.json 仅多了 vconsole 一行、无其他依赖被改，排除依赖 churn 导致 K 线抓取坏掉的可能。
- 星标K线「K线加载不出来」：极可能是 QDII 圆点开关默认 `qdiiOnly=false`（只显示非 QDII），而用户只加了 QDII 基金 → displayList 过滤成空 → 整页空白像「加载不出」。
  - 修复：`StarKLinePanel.refreshList()` 里增加自动兜底——当前是默认 off 且「非 QDII 组为空、QDII 组有数据」时把 `qdiiOnly` 自动翻转成 true，避免空白页；用户手动切过的不抢。
  - 注意：若仍空白，可能是真实抓取/JS 报错；开关已修好，让用户打开开关看 VConsole 控制台红字即可定位。
- vue-tsc -b 通过。
