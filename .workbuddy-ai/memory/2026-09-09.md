## 星标K线卡片：信息条 + 累计涨幅和按钮重叠修复（2026-09-09 追加）

用户原话「手机版的星标K线 基金名和涨跌幅重叠 累计涨幅 和 放大 删除按钮重叠，
手机版本不要放大按钮了 你看下怎么设计UI 不挡」。

**根因（全屏模式共用）**：MiniKLineChart 在 canvas 里用**死坐标**画信息条三段
（名称左 / 涨跌幅居中 / 累计涨幅最右），窄图（手机 186px、全景列 ~145px）上名称
会盖到居中的涨跌幅，收益率又正好被右上角悬浮按钮压住。Y 轴顶部刻度（"30.7%" 之类）
也在按钮底下。一共三个重叠。

**修法（一次性治三处）**：

1. **MiniKLineChart 抽出 `computeLayout(width, height)`**，drawChart 和 handleCanvasClick 共用
   ——原来两处各写一份 padding，命中判定会漂移。
2. **信息条右对齐量按 measureText 实际宽度从右往左排**：累计涨幅 → 市值 → 当日涨跌幅，
   右边界让开 `topRightReserve`。放不下整段不画，宁缺勿重叠。
3. **窄图切两行**：`width < 280 && height >= 130` → 信息条 26px 高，
   基金名独占第一行（整行宽），涨跌幅 + 累计涨幅挤第二行右半边。
   宽图（≥280 或 <130 高）保持单行 14px，沿用原行为。
4. **名称按像素二分省略号截断**（canvas 没有 text-overflow）。
5. **窄图省掉「净值 / 估值」后缀**（约 26px），让基金名能完整显示。
6. **Y 轴顶部刻度碰撞**：当 `y < 26 && reserve > 0` → 右对齐到 `width - reserve - 2`，让开按钮。
7. **加 prop `topRightReserve`**：右上角悬浮按钮占的宽度（px），父层按按钮数算好传进来。
   默认 0 = 没按钮（独立全屏 + 详情弹层就是这个状态）。

**StarKLinePanel 配合改动**：
- 加 prop `showDetail?: boolean`（默认 true），为 false 时只渲染「移除」按钮。
- 加 `controlReserve` computed：根据按钮数算像素宽度传给图表。n=0 → 0，n=1 → 26，n=2 → 50。
- 公式 `2 + n*22 + (n-1)*2 + 2`（2px 容器右边距 + 22px 按钮 + 2px 间距 + 2px 呼吸）。
  改按钮尺寸 / 间距时只动这一处，组件会自动跟上。

**MobileStarKLine 应用**：
- `:show-detail="false"` —— 移除「放大」按钮，按用户要求
- `:aspect-ratio="'4 / 3'"` —— 卡片从 186×116（16/10）拉到 186×140，
  触发「两行信息条」分支，名称独占一行不截断
- 权衡：每屏能看的图从 ~12 个降到 ~10 个，换 K 线更可读

**桌面不受影响**：
- 全景大屏列 180×112：height < 130 → 走单行分支，按钮 2 个 → reserve=50，
  名称右对齐 + 省略号，收益率 / 涨跌幅挤在右侧让开按钮。
- 独立全屏页（minItemWidth=300）：width ≥ 280 → 单行无省略号，后缀也保留。
- 控制按钮：手机 1 个，全景 2 个，独立页 2 个。桌面全景 / 独立页的「放大」按钮保留。

## 手机星标K线页是否有 60 秒自动刷新（结论：**有**，已实测）

用户问「手机版本这个星标k线页面 有没有60秒自动刷新估值」。查证过程与结论：

**链路**：`StarKLinePanel.startAutoRefresh()`
→ `setInterval(() => loadRealtime(true), 60000)`
→ `ownValuation.loadFundData(codes, force=true)`
→ `fetchFundAccurateData(code, isQDII, true)`（每个星标基金一次）
→ 写回 `liveFundData` → `realtimeFor(code)` 重算 → 子图 `props.realtime` 变化 → 重绘。

**关键分支** `if (props.liveData) return`：
- 全景大屏传了 `liveFundData` → **跳过**（由页面自己的刷新周期负责，避免双重拉取）
- 手机页 `MobileStarKLine` 没传 → **定时器真的会跑** ✅
- 独立页 `StarKLine.vue` 也没传 → 同样会跑

**子图自带的 60s 定时器是空转，不是重复请求**：`MiniKLineChart` 有自己的
`refreshTimer = setInterval(() => loadRealtime(), 60000)`，但 `loadRealtime()` 开头
`if (props.realtime) return`，而面板恒传 `:realtime="realtimeFor(code)"`。
所以 N 个图只有 1 个有效定时器，不存在请求放大；只在某只基金取不到估值（realtime 为 null）时兜底补拉。

**生命周期干净**：`onMounted`/`onActivated` 起，`onDeactivated`/`onUnmounted` 停；
`keep-alive include` 不含 mobile-star-kline → 离开即卸载，不漏定时器。

**实测方法**（`probe-mobile-autorefresh2.mjs`）：临时把 `StarKLinePanel` 的 `60000` 改成 `3000`
跑完再改回（已 `grep PROBE-TEMP` 确认无残留）。另用 `addInitScript` 劫持 `window.setInterval` 记录延迟。
结果：注册了 2×60000（MiniKLineChart）+ 1×3000（StarKLinePanel，即改过的那个）；
10 秒内 pingzhongdata 请求 17 → 41（+24），确认定时器在跑且真的在拉数。`vue-tsc -b --force` 退出码 0。

**踩坑记录**：
- 第一版探针只统计 `pingzhongdata`，得出 `newRequestsIn10s: 0` 的假阴性。
  真实原因是估值走的是 `fetchFundEstimateFast → fetchTopHoldings`（拉 `fund.eastmoney.com/{code}.html`
  按重仓股算），**不是** `fundgz` 那个 JSONP；而 60s 刷新实际打出去的是 `fetchNetValueHistoryFast`
  的 pingzhongdata。**统计口径选错会得出完全相反的结论。**
- `page.route` 改写 Vite 模块源码（把 60000 替换成 3000）没生效；直接改源文件再改回更可靠。
- 探针必须把持仓 seed 成 `isUpdated:false / currentValue:0`，否则 `loadFundData` 快路径一次请求都不发。

**顺带确认的两个「刷新短路」**（已写进 MEMORY.md）：
1. `loadFundData` 快路径连 `forceRefresh=true` 都短路 → 净值落地后 60s 刷新自然变空转（正确行为）
2. `fetchFundEstimateFast` 非交易时间 + `forceRefresh=false` → 直接返回持久化缓存

### 后续：一次刷新到底打多少请求（实测 26 次 / 6 只星标）

探针 `probe-auto-cost.mjs`（6 只星标，把 60000 临时改 3000 测 3 个周期取平均）：

| 接口 | 每周期（≈60s）请求数 |
|---|---|
| pingzhongdata | 18 |
| qt.gtimg | 7 |
| push2delay | 1 |
| **合计** | **26** |

≈ **每只基金每轮 4.3 次请求**。手动点刷新（`.msk-refresh` → `forceRefresh`）也是 26 次，
巧合但量级一致。手机页**本来就已有手动刷新按钮**（我之前说"要不要加一个"是记错了，已纠正）。

**真正的成本不在请求数，在流量**（`fetchFundAccurateData` 里两处叠加）：
1. `fetchNetValueHistoryFast(code, 2, forceRefresh=true)` → **直接跳过缓存**（fundFast.ts:562）
2. 该接口的 URL 是 `https://fund.eastmoney.com/pingzhongdata/${code}.js?v=${Date.now()}`
   —— **`?v=Date.now()` 打掉 HTTP 缓存**（fundFast.ts:434）

也就是说 `days=2` 只是解析时取 2 条，**实际每次都把该基金从成立至今的完整净值历史整个重新下载一遍**。
盘后（21 点测的）净值根本不会变，这 26 次请求是纯浪费。

**建议的修法（未实施，需用户确认，因为动的是共享估值语义）**：
`StarKLinePanel.startAutoRefresh` 只在交易时间传 `force=true`，盘后传 `false`：
- `force=false` + 非交易时间 → `fetchFundEstimateFast` 直接返回持久化缓存，**零网络**
- `force=false` 的 `fetchNetValueHistoryFast` 仍有「cache 最新日期 ≠ 今天」判定，
  傍晚净值发布后照样能被拉到，不会漏更新

只改 `StarKLinePanel`（手机页 + 独立页），**不动 `useFundValuation` / `fundFast.ts`，不影响全景大屏**。
探针必须先 seed `isUpdated:false`，否则 boot 后 `initHoldings→refreshEstimates` 会把它写成 true，
`loadFundData` 快路径生效 → 一次请求都不发，测出来是 0（本次实测 boot 后仍是 false，所以测到了）。
