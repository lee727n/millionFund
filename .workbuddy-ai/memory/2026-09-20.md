## 星标K线点击弹窗边界自适应 + 加仓/减仓市值不更新修复

**Issue 1 — 弹窗下半部分看不到：**
`src/components/MiniKLineChart.vue` 点击买卖点提示框只夹了 顶/右 两边界（原 `boxY<padding.top` 翻到下、`boxX+boxWidth>right` 翻到左），基金「买入后下跌」时买点偏高、提示框翻到点下方会溢出底边被裁切。
修法：先按「点上/下区域→放上方/下方」「点左/右区域→放右/左」选主方向，再用四边界兜底夹紧（含 bottom: `boxY+boxHeight>height-padding.bottom` 与 left: `boxX<padding.left`）。任何角落点击都能完整显示。

**Issue 2 — 加仓/减仓总市值不变（002163 加仓5w仍显示12.11W）：**
根因：`src/stores/holding.ts` `addOrUpdateHolding` 只做字段合并，**从不重算 marketValue**；`PanoramaDashboard.submitTrade` 改 `cur.shares` 后调 `addOrUpdateHolding`，持久化的还是旧 `marketValue`。刷新时 `updateHoldingWithAccurateData` 会重算，但即时显示是错的。
修法：`addOrUpdateHolding` 内当 `shares>0 && currentValue>0` 时强制 `marketValue = shares × currentValue`。该不变量恒成立，不会误伤 `submitCostAdjust`（其落入的 marketValue = newShares × latestNetValue，重算等价）。
结论：加仓/减仓现在会立即改变总市值（含汇总里的 totalValue，它累加 `h.marketValue`）。

## 量化观察「改来源仍在观察」bug 修复（008984 财通科技创新）

用户反馈：全景量化观察点基金 → Detail(`window.open('_blank')` 新窗口) 改来源到京东 → 回全景刷新，基金还在量化观察。

**双重根因**：
1. **跨标签页内存态过期**：`goDetail` 用 `window.open('_blank')` 在新窗口开 Detail，Detail 改了来源写回 localStorage，但原全景标签页的 `holdings` 是内存态，不会自动更新；而 `refreshAll` 从不回读 `holdings`，仅重拉实时价 → 软刷新也看不到变更。`onMounted` 的 `initHoldings` 只有整页重载才跑，所以软刷新无效。
2. **同 code 多条记录**：`addOrUpdateHolding` 旧用 `findIndex` 只更新第一条；若同一 code 有两条 observe 脏数据，改来源只动一条，剩下那条仍在观察。

**修法**：
- `src/stores/holding.ts` `addOrUpdateHolding`：改为「匹配全部同 code → 以第一条为基底合并 record → `filter` 删掉全部同 code 再回填唯一一条」。既让来源/加仓对所有重复记录生效（根治现象），又顺手收敛脏重复（防重复展示+市值重复累加）。⚠️ 不能对 precomputed 索引逐个 `splice`（位移错位），必须用 filter+push/insert。
- 新增跨标签页同步：`registerStorageSync()` 监听 `storage` 事件（仅其它标签页写入时触发），key 为 `fund_holdings` 时调 `syncHoldingsFromStorage()` 把 localStorage 回读进内存；`storage.ts` 的 `STORAGE_KEYS` 改为 `export`。`syncHoldingsFromStorage` 经 store return 暴露。
- `PanoramaDashboard.refreshAll`：`forceRefresh=true`（手动 ↻）时先 `holdingStore.syncHoldingsFromStorage()` 兜底，确保手动刷新也反映来源变更；自动 60s tick 不回读避免无谓 churn。

`npx vue-tsc -b` 通过（exit 0）。node 单测覆盖：双 observe→JD 收敛成 1 条且离观察、单 observe→JD 离观察、加仓份额累加+市值重算、全新基金新增——均符合预期。
