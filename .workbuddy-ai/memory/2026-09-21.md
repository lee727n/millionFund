## 全景大屏左侧持仓：京东账户被截断 + 滚动条 bug

用户反馈：左侧持仓「京东账户」下面明明还有空间，却出现内部滚动条、基金显示不全；并怀疑是底部 tabbar 隐藏但仍占位。

排查结论：
- **tabbar 不是原因**：`App.vue` 用 `v-if="showTabbar"` 渲染底部栏，隐藏时不进 DOM、零占位；`.col-scroll` 仅 `padding-bottom:12px`，无 tabbar 预留高度。
- **真因**：每个账户区块的 `.fund-grid-scroll` 有内联 `maxHeight: acc.height`，而 `DEFAULT_ACCOUNT_HEIGHTS.JD=130`（storage.ts:708），JD 基金网格被死死压在 130px 内 → 内部滚动条 + 截断；与此同时整列 `.col-scroll` 还有约 220px 余量，所以出现「下面有空位却滚动」。

修复（PanoramaDashboard.vue）：
- 去掉 `.fund-grid-scroll` 的内联 `maxHeight` 绑定、CSS `max-height/overflow` 及各账户覆盖（`.block-ali/tx/jd`）。账户区块改为按内容自适应高度，整列 `.col-scroll` 统一滚动。
- 顺带移除已失效的「账户高度拖拽分隔条」(`.account-resizer` 全套：模板 div / 样式 / `onAccountResizerDown/Move` / `draggingAccountResizer` / `accountHeights` / `accHeight` / `resetAccountLayout` 里的高度部分)，保留 ⋮⋮ 手柄拖拽换顺序。
- storage.ts 的 `DEFAULT_ACCOUNT_HEIGHTS`/`MIN_ACCOUNT_HEIGHT`/`get/savePanoramaAccountHeights` 暂留（无害的未用导出），不再从 vue 引入。
- `npx vue-tsc -b` 通过（exit 0），dev server 5173 HMR 已生效。

⚠️ 设计取舍：原来是「每块固定高度(可拖调)+块内滚动」窗格式；现改为「块随内容生长 + 整列滚动」。若用户想要仍可单独收缩某账户区块的窗格能力，需另做方案（如块内 min-height 或折叠）。

## 京东3基金仍无买点：backfill 日期护栏 bug 修复

用户复查：重开后 3 个京东基金（方正富邦/银海中小盘/华夏上证科创）仍无买点，怀疑没走到 `initHoldings`。

排查：
- `initHoldings` 实际已接好（Home/Holding/Panorama/Portfolio/StarKLine/Detail onMounted + BackupActions 都调），会跑。
- **真因**：`backfillTodayBuyTrades`（holding.ts）护栏 `h.buyDate !== today` → 基金是 09-20 加的，今天 09-21，`buyDate!==today` 直接 `continue` 跳过，永远补不到买点。原护栏只修「当天添加当天重开」的，跨天失效。
- 另：原逻辑还会用今天价 `h.buyNetValue=netValue; h.shares=amount/netValue` **改写份额**，对历史持仓会破坏真实成本基数（错）。

修复（holding.ts）：
- 函数改名 `backfillBuyTrades`，**去掉 `buyDate===today` 护栏**：只要持仓缺 `buy` 交易就补（不变式「每持仓都有 buy 交易」；缺它的只可能是老代码创建的，补建即恢复）。已有 buy 交易的（含加仓/减仓过的）被 exists-check 跳过，零误伤。
- **不再改写 `shares`/`buyNetValue`**：用现有 `buyNetValue`（兜底 `currentValue`）建一笔 `estimated:false` 的 buy 交易，仅补「买点标记」，成本基数沿用不变。`resolveAddValue`/`fetchFundAccurateData` 在本函数不再使用，已从 import 移除（`fetchFundAccurateData` 仍被 refreshEstimates 用，保留）。
- `initHoldings` 调用改名同步。
- 渲染侧确认（MiniKLineChart.vue:737-773）：买点只在「交易 date 命中 filtered 可见范围」或「是今天+延伸点」才画；3 基金 buyDate 在近期范围内，交易一建即出买点，无渲染坑。

⚠️ 关键使用提示（告诉用户）：Vite **HMR 不会重跑 onMounted/initHoldings**（store 被保留），所以改完代码后必须**整页硬刷新（Cmd/Ctrl+R）**或重开 App，才会触发 `initHoldings→backfillBuyTrades`；HMR 软更新只看得到代码变化、不会补买点。全自动刷新/pull-to-refresh 也会重跑（那些调用点同样走 initHoldings）。
`npx vue-tsc -b` 通过（exit 0）。

## 删除基金后买点/交易孤儿 + 重加重复买点（与「星标K线保留点位」旧需求冲突排查）

用户现象：删掉华夏上证科创持仓后重加，星标K线仍显示 9.18 买点；在 Detail 删了交易记录，星标K线还有点。

排查结论（真因）：
- 买点数据源 = `getTradesByCode`（MiniKLineChart 直接读交易记录），**不是**星标快照 `StarredFundMeta`（后者只冗余 name/addedGain/buyNetValue/成本线，无交易数据）。
- `removeHolding`（storage.ts:185）只过滤持仓、完全不碰交易 → 删持仓后该 code 的买入交易变**孤儿**仍留在 TRADES，星标K线继续画买点。
- 重加时 `createBuyTrade` 新建一笔买交易却没清孤儿 → 出现重复买点（9.18 孤儿 + 9.21 新加）。用户在 Detail 删的很可能是 9.21 那笔，9.18 孤儿留下。
- 旧需求「删基金星标K线仍保留点位数据」= 快照保 name/成本线，与买点(来自交易)不是同一机制；真正的冲突是「删持仓不级联删交易」留下的孤儿。

修复：
1. `Holding.vue submitForm`：全新添加（此前无持仓）时，建买入交易前先清掉该 code 的全部 `buy` 孤儿交易（`getTradesByCode`+`removeTrade`），消除重加重复买点。仅全新添加才清，编辑不动。
2. `holding.ts removeHolding`：删持仓后级联——**仍星标→保留买点**（旧需求：星标K线继续看）；**未星标→删掉该 code 全部交易**（彻底移除，孤儿不再挂买点/交易记录）。需 import `saveTrades,isStarredFund`。
- `isStarredFund` 与 `removeHolding` 同在 storage.ts，函数声明提升可互调。

用户现存重复数据清理：二选一——(a) Detail 里删掉 9.18 那笔孤儿交易；或 (b) 删掉该持仓(星标→交易保留)再重加(新持仓→触发修复#1清孤儿，只剩 9.21)。
⚠️ 使用提示：想彻底移除某基金买点 → 先取消星标再删持仓（或本就未星标直接删）；想保留观星 → 删持仓会保留买点（旧需求）。
`npx vue-tsc -b` 通过（exit 0）。

## 东方惠新：删加仓记录后重加数据错（添加基金对话框覆盖基础持仓）

用户场景：东方惠新基础持仓 7.11W，「今天加仓 5W」→ 12.11W。在 Detail 删除该 5W 加仓记录（handleDeleteTrade 会 `holding.shares -= trade.shares` 回滚持仓）→ 正确回到 7.11W 基础。但之后用「添加基金」对话框重加 5W，总值没回到 12.11W（停在约 7W）。

**根因**：`src/views/Holding.vue` 的 `submitForm` 对「已存在 code」也走 overwrite —— `record.bares=calcShares`(仅表单金额)、`buyNetValue=currentNetValue`、`buyDate=today`，把基础 7.11W 整个覆盖成 5W 那笔，导致总值对不上、买点也错。

**修复**：`submitForm` 改为分支——
- 已存在持仓（`getHoldingByCode` 命中）→ 按「加仓」语义 **累加份额** `shares += addedShares`，`buyNetValue/buyDate` 不动（保留基础成本），只额外建一笔今日 buy 交易（买点）；
- 全新持仓 → 维持原逻辑（建 record + 清孤儿买点）；
- 末尾统一 `createBuyTrade` 用 `date=today / amount / netValue=currentNetValue / estimated`。

`isEditing` 全文件从未被置 true（只有 `openAddDialog` 置 false），该对话框纯「添加」无编辑路径，改写安全。`npx vue-tsc -b` 通过（exit 0）。

**给用户的修复方式**（本地 localStorage 我无法直改，无本机备份文件）：基础 7.11W 删除回滚后应是完好的，直接「加仓 5W」（全景加仓对话框，或修复后的添加基金对话框）即 12.11W+买点。若之前错误重加已把基础覆盖成 ~5W，则先「调成本」设回基础市值或导出备份让我精确修 JSON 再导入。
