# 2026-10-15 工作日志

## 全景大屏：现金余额联动交易（Cash ↔ Trade 自动增减）

### 1. 需求
- 账户**新增基金 / 加仓（buy）** → 自动从对应账户现金余额**扣减**交易金额。
- 账户**减仓 / 清仓（sell）** → 自动把交易金额**加回**对应账户现金余额。
- 顶栏「现金余额」总和、账户现金 chip 随之实时刷新。

### 2. 实现（统一出口 useFundTrade.createTrade）
- `createTrade` 新增可选参数 `adjustCash?: boolean`（默认 true）。
- 落盘 `addTrade` 之后：若 `adjustCash !== false` 且 `source ∈ {ali,TX,JD}` 且 `amount>0`，按 `type` 调现金：
  - `buy` → `cash[source] -= amount`；`sell` → `cash[source] += amount`；其余类型（dividend/auto_invest）不动。
  - 只维护 支付宝/腾讯/京东 三账户现金；`other`/空 source 跳过。
- `createBuyTrade` 透传 `adjustCash`。

### 3. 排除「历史/批量/自愈」类建交易（防误扣）
- `stores/holding.ts` 的 `backfillBuyTrades`（自愈补齐买点）→ `adjustCash:false`。
- `Holding.vue` 批量导入 → `adjustCash:false`（存量数据迁移）。
- `ScreenshotImport.vue` → `adjustCash:false`（且本就不带 source，天然不动现金）。
- 显式单加（Holding 单加）、交易弹窗（Home/Panorama/Detail）默认 true → 实时联动。

### 4. 顺带修复：三处 submitTrade 的「先建交易后校验」时序 bug
- 原 Home/Panorama/Detail 的 `submitTrade` 先 `createTrade` 再校验「减仓份额≤持仓」，导致减仓超额时会**已建交易、已调现金**却又回退，数据错乱。
- 改为：先把 `cur = holdings.find(...)` 提出来、在 `createTrade` 之前做减仓超额校验（不通过直接 return），再建交易并更新持仓。
- Panorama 提交成功后 `accountCash.value = getPanoramaAccountCash()` 让顶栏/账户现金即时刷新（Home/Detail 不显示现金，无需回读）。

### 5. 校验
- `npx vue-tsc -b` 通过（EXIT 0）。

### 6. 备注
- 现金是「手动基线 + 交易联动」的混合：用户手动录入的现金视为当前可用资金起点，之后的买/卖交易在此基础上自动增减。
- 未做「按全部历史交易回算现金」的 reconcile 功能；若用户后续想把存量交易也并入现金视图，可另加一个「从交易记录重算」按钮（遍历 trades 对 ali/TX/JD 求和）。
- 删除持仓不级联删交易（既有行为），故删除持仓不会回退现金（现金已在交易时结算）。

## AI追踪：当天转换「累计」误显为当日涨跌幅（修复）

- 现象：今天新增的转换（无日期=今天），两只基金「累计」显示成 +1.61% / +0.63%（其实是当日涨跌幅），用户认为应为 0。
- 根因：`confirmAddRecord` 无日期分支把成本基准 `sellNav/buyNav` 冻结为「添加那一刻」的 `fetchFundAccurateData().currentValue` 快照；若在今日净值发布前添加，该快照=昨天净值。而展示用的 `fundPrices[code].value` 是重新拉取的实时值，二者相减把基金当日涨跌幅当成「转换收益」。fetchCurrentPrices 里的 auto-confirm 本应在今日净值发布后把基准改写为当日净值，但只在刷新时触发、且盘中历史无今日记录 → 整天都显示错误值。
- 修复：新增 `isConversionSameDay(record)`（对比 record.date 与本地当天），在以下位置对当天转换强制「累计=0」（当日真实涨跌本就由「今日」字段承担）：
  - `src/views/AITracking.vue`：`getChangeText/getChangeClass/getCalcProcess/getCalcProcessCombined/getStatusText/getStatusClass/getDiffText/getDiffClass`，以及 `records` 排序、`successCount`、`totalChange` 聚合（当天记录从成功率/总累计中排除）。
  - `src/views/AITrackingDetail.vue`：`getTotalChangeText/getTotalChangeClass/getStatusText/getStatusClass/getDiffText/getCalcProcessCombined`（date 由路由参数传入）。
- 次日 record.date≠今天，走正常逻辑；auto-confirm 会在重开/刷新且今日净值发布后把基准锁定为当日净值，故次日「累计」=真实转换后收益。
- `npx vue-tsc -b` 通过（EXIT 0）。
