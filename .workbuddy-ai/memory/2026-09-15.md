## 全景「累计」差异根因 + 口径规则（用户「教给你了」）

现象：左列持仓「累计」(-17.6%) 与第2列星标K线「累计」(-21.33%) 不一致。
根因 = **公式分母不同**（同一 holding 对象的两个字段）：
- `addedGain` = (现价−买价)/买价 ×100 = 利润÷成本（**真 ROI**）。`holding.ts:286`
- `profitRate` = 利润÷当前市值 = (现价−买价)/现价 ×100。`holding.ts:267` / `StarKLinePanel.vue` 旧 :134
下跌时 profitRate 分母更小 → 更负，正好对应 -21.33 < -17.6。数值可反推验证（左 -17.6% → 右 -21.36%）。

**关键更正**：我一度以为 Detail/Home/Holding 的「收益率」也用 profitRate；实测并非如此——
- Detail.vue `holdingDetails.profitRate` 是**本地重算**成 (现价−买价)/买价（真 ROI），变量名误导但值对；
- Home/Holding 单基金「累计」也是 `addedGain`。
所以真正错的只有：全景左列 + 观察列表（上一轮误改成 profitRate）+ 星标K线信息条（传 h.profitRate）。

**用户确立的规则（长期约定）：累计/收益率 一律用真 ROI = addedGain，不许用 profitRate。**
本回合已把上面 3 处改回 `addedGain`（左列/观察列表用 `fund.addedGain`，星标 `StarKLinePanel:134` 改 `h.addedGain`），
显示位数保持 `.toFixed(2)`。`npx vue-tsc -b` 通过。现全景左列 / 星标K线 / Detail / Home / Holding 单基金「累计·收益率」口径统一为 addedGain。
- 例外：Holding 顶部「收益率」汇总 = `summary.totalProfitRate`（组合层 = 总收益÷总市值），属组合级聚合指标，未动。

## 全景持仓「净值/涨幅对不上账户」根因 + 修复（用户疑问）

现象：净值都更新了，但全景左侧持仓这部分 currentValue/今日涨幅 还是旧的、和账户实际更新的净值对不上，疑是「还在用估值」。
**不是数据源问题**：`fetchFundAccurateData` 在 `isWeekday && isNavUpdated` 时正确返回 NAV + `dayChange=navChange`。

**真因 = `isUpdated` 粘性布尔陷阱**：`holding.isUpdated` 持久化布尔，被置 true 后**不会因日历日推进复位**。
`refreshEstimates()`（holding.ts:195/199）和 `useFundValuation.loadFundData` 快路径（line 51）都直接读这个布尔决定「跳过重拉」——
结果隔了几天再开 App，持仓停在「上次更新那天的净值/涨幅」，永不重拉。左侧面板读的就是 holding 的 `currentValue`/`todayChange`，所以错显。

**修法**：两处跳过条件改为 `holdingNavIsCurrent(h)`——用持仓自己的 `valueDate` 重跑
`isNavUpToDate({ nav: h.currentValue, navDate: h.valueDate, isQDII, today: getProgressDateStr() })`，
只有 valueDate 已是今天（或盘前归上一工作日）才跳过快路径，否则一律重拉。`isUpdated` 字段保留（进度条/状态徽标仍读它）。
改动：`holding.ts` 新增模块函数 `holdingNavIsCurrent` + 改 `refreshEstimates` 两处；`useFundValuation.ts` 加 import + 同名函数 + 改快路径守卫。`npx vue-tsc -b` 通过。
相关：Detail.vue:614 也有 `holding.isUpdated` 快路径同款模式（本次未动，先观察）。

## Request 13：盘后/跨设备 持久化估值串味（5.04% / 4.48% / 2.24%）

现象：盘后4点净值未更新，三个端显示不同估值（全景持仓5.04%、Detail4.48%、手机2.24%）。
根因 = `fetchFundEstimateFast` 把 `FundEstimate` 存进 `persistCache`（localStorage `fund_estimate_${code}`）时**不带日期戳**，
非交易时间（含盘后 >=15:00）直接 `return persisted` 且无任何新鲜度校验——
手机当天没打开过 → 落的是上一次打开时的旧估值（2.24%）被当今天涨幅。

**修法（src/api/fundFast.ts + src/types/fund.ts）**：
- `FundEstimate` 新增可选 `estimateDate?: string`（估值所属自然日）。
- `fetchFundEstimateFast` 把时间判定提到最外层；持久化 `result` 时打 `estimateDate: getCalendarDateStr()`。
- 复用条件 `canReusePersisted = persistedIsFinal || isBeforeTrading || !isWeekday`，其中
  `persistedIsFinal = persistedIsToday && (!isAfterTrading || 快照小时>=15)`。
  - 盘后且持久化是旧日期/无日期（手机隔天没打开）→ **强制重抓当天估值**（不再用旧估值）
  - 盘后且持久化是当天但盘中快照(如14:00)→ 重抓收敛到收盘最终估值（解 4.48 vs 5.04）
  - 盘后且当天收盘快照(>=15:00)→ 复用（省网络）；盘前/周末旧估值→复用（那两个分支不选用估值，无害）
- 三个兜底（空持仓 / prevNav<=0 / catch）也改为仅 `persistedIsToday` 才回退，否则抛错让上层走净值 fallback，
  杜绝旧估值被误当今天涨幅返回。
- `updateHoldingWithAccurateData` 的 `valueDate = data.estimateTime?.split(' ')[0]`（估值时为"15:00"垃圾串）经核实
  不会造成冻结（isNavUpToDate 对非法日期返回 false → 走重拉），故**未改**。

`npx vue-tsc -b` 通过（exit 0）。另写纯 JS 验证脚本复刻判定分支，8/8 场景通过（旧日期/无日期盘后强制重抓、当天收盘复用、盘中快照重抓收敛、盘前周末无害复用、交易时间恒重抓）。
