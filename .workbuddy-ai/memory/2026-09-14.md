## 星标K线交易 tooltip：份额 → 涨幅（已实现 + 验证）

用户：K线图点上去 tooltip 最后一项是「份额」，没用，换成「涨幅」——计算从区间起点到最新估值/净值的涨跌幅度，公式参考之前的涨跌幅。

**改动**：`src/components/MiniKLineChart.vue`
- 交易类 tooltip（type==='trade'）把最后一行 `份额: ${shares}` 换成 `涨幅: ±X.XX%`。
- 公式（与图上累计收益率线 / `getPerformanceData` / drawChart 的 extendedPerf 完全一致）：
  `firstValue = getFilteredData()[0].value`（区间首根净值）
  `latestValue = rt.value.currentValue（>0 则取，含实时估值）?? filtered[末].value`
  `gainPct = firstValue>0 ? (latestValue-firstValue)/firstValue*100 : 0`
- 绘制循环里给「涨幅」行按正负染色（up/down），和 累计收益率线一致。
- 只动 trade 分支，ttrade tooltip（做T收益/收益率/持有天数）不动。

**重要口径澄清**（易踩坑）：
- `props.returnRate` ≠ 这里算的「区间累计涨幅」。`props.returnRate` 在 StarKLinePanel 里取的是
  `h.profitRate`（持仓成本收益率，即买入至今总回报），信息是「since 成本」；
  而 tooltip 的 涨幅 是「区间首根净值 → 最新估值/净值」，是图表自身的累计收益率口径。
  两个指标不同，标签也不同（累计收益率 vs 涨幅），别混。
- 区间累计涨幅的「最新」优先取实时估值 `rt.value.currentValue`（`props.realtime ?? realtimeData.value`），
  盘后无估值时回落到最后一根已发布净值。

**验证**：`probe-tooltip-gain.mjs`（fillText 间谍 + 网格点击命中交易标记）。
结果：`["加仓 2026-07-01","金额: 1300.00 元","净值: 1.5000","涨幅: +2.09%"]`，
`hasShares:false / hasGain:true`，无 console error。`vue-tsc -b --force` 退出码 0。

（注：此改动与上次「60s 自动刷新」是两个独立任务，互不干扰。）

## 全景交易记录「净/估」标签错显 bug（已修复 + 验证）

用户：全景大屏交易记录里 国联安优选行业混合 今天的减仓点位显示「净 -0.37%」，但值是用估值算的，
今天净值未更新，应该显示「估」。按既定逻辑：没更新净值用「估」，更新了才用「净」。

**根因**：交易记录标签来自 `trade.estimated`（`PanoramaDashboard.vue:1553` `{{ trade.estimated ? '估' : '净' }}`）。
`useFundValuation.loadFundData` 的 API 路径（`holding` 未更新时走这里）会调
`updateTradesByCode(code, info.nav, info.navDate)`。盘中今天净值未发布时 `info.nav` 其实是**上一期**净值，
而 `updateTradesByCode` 原逻辑 `shouldUpdate = t.estimated || (navDate && t.date === navDate)` 会把今天用估值建的单
（`estimated:true`）**无条件确认成净值**：`t.estimated=false` 且 `t.netValue` 被上一期净值覆盖 → 标签错显「净」、份额算错。
Detail.vue / TradeCenter.vue 有第二道「恢复 estimated」补丁所以没暴露，全景的 `useFundValuation` 没有，于是只在全景出错。

**修复**：`src/utils/storage.ts` 的 `updateTradesByCode` 加 `navIsCurrent` 参数，只有「这期净值是今天该拿到的那一期」
（`navIsCurrent`）才把估值交易确认成净值：
`shouldUpdate = (navIsCurrent && t.estimated) || (navDate && t.date === navDate)`
`navIsCurrent` 由 `isNavUpToDate`（自然日 + isQDII）判定，QDII 滞后也认。原 `t.date===navDate` 兜底分支保留。
同步把 6 个调用点都透传该 flag：
- `useFundValuation.ts:64` 快路径传 `!!holding.isUpdated`；`:86` API 路径传 `info.navIsCurrent`
- `Detail.vue:114` 传 `data.navIsCurrent`；`:629` 快路径传 `!!holding.isUpdated`；`:652` 传 `accurateData.navIsCurrent`
- `TradeCenter.vue:123` 传 `data.navIsCurrent`

**验证**：`probe-panorama-navtag.mjs`（Playwright，mock 网络：最新净值日期=昨天、盘中用估值）。
- 修复后：NAVTAG="估"，`estimated:true`，netValue 保持估值口径 2.5098。
- 临时回退旧逻辑对照：NAVTAG="净"，`estimated:false`，netValue 被覆盖成 2.48（上一期净值）。
before/after 干净对照确认修对。`vue-tsc -b --force` 退出码 0，无 TEMP 残留。

## 全景「还显示净」= 缺 heal 补丁（已补）

用户复诊：上一条修复只防「以后不再污染」，但**已被旧 bug 污染的记录仍留在 localStorage**
（`estimated:false` + netValue 被覆盖成上一期净值），刷新时 `updateTradesByCode` 看到 `estimated:false` 不会翻回 → 仍显示「净 -0.37%」。

**补丁**：`useFundValuation.loadFundData` API 路径补上与 Detail.vue/TradeCenter.vue 一致的 heal：
`if (!info.navIsCurrent && !holding?.isUpdated)` → 把今天 `!estimated` 的交易恢复 `estimated:true`
（用 `getCalendarDateStr()` 比 `t.date`，存 `getTrades/saveTrades`）。仅恢复标签，不动 netValue（与另两页一致）。
净值发布后（`navIsCurrent=true`）下次刷新 `updateTradesByCode` 自动确认成净值。

**验证**：探针 seed 成 `estimated:false` + netValue=2.48（真实污染态），加载后 → NAVTAG="估"、`estimated:true`。
（探针坑：trade.date 必须 = 应用内真实 `getCalendarDateStr()`，否则 heal 的 `t.date===today` 不匹配；之前硬编码 2026-09-09 而系统时钟 2026-09-14 导致首次漏触发，改用真实时钟后通过。）
