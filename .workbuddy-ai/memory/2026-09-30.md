# 2026-09-30

## Bug 修复：全景星标K线 002910（易方达供给改革）点击 9.30 点显示错误 tooltip

- 现象（用户纠正后）：Detail 页与全景星标K线**图形和点完全一致**（9.30 加仓 2000 的点都画出来了）。真正的问题是**点击 9.30 那个点**时，弹出的交易信息显示的是 9.29 加仓，而不是 9.30 的 2000 加仓；Detail 里点击显示正确。
- 根因：点击命中逻辑 `MiniKLineChart.handleCanvasClick` 与 `drawChart` 坐标**不一致**：
  1. 用 `findDateIndex(filtered, trade.date)`（带 7 天兜底）把 9.30 交易误匹配到 filtered 里最近的 9.29 点；
  2. `toX` 用 `perfData.length` 而非 `extendedPerfData.length`，延伸点 x 坐标没被纳入，点不中；
  3. `break` 首命中即停，9.29 交易先命中挡住 9.30。
- 修复：`handleCanvasClick` 复用 `drawChart` 的延伸点逻辑——算 `extendedPerfData`/`hasExtension`/`todayStr`，`toX` 用 `extendedPerfData.length`；交易命中改**严格日期匹配**（`filtered.findIndex` 日期全等），匹配不到再判 `hasExtension && 今天`→`extendedPerfData.length-1`；并改取**最近命中**而非首命中。`vue-tsc -b` 通过。
- 回退上一条错误前提改动：先前误以为「点消失」而加的 `nav` 兜底（`realtimeFor` / `MiniKLineChart.loadRealtime` / `useFundValuation` 的 `navChange`）已**回退**。理由：用户确认点「没改之前就画出来了」，且估值失败用旧净值当今天点会显示错误数据，保持 `currentValue>0` 原闸门更诚实。如后续真要防御批量超时，再按需重加。

## Bug 修复（续）：点击红点高亮位置错位（跑到下方很远）

- 现象：上一轮修完后，点击 002910 的 9.24 加仓点，tooltip 信息对了（3000 元那条），但**高亮红点不在原交易标记上，而是跑到图表下方 -10.6% 附近**。其他基金如东方人工智能也偶有此问题，只是偏移小不明显。
- 根因：`handleCanvasClick` 的 `toY` 范围只算了 `fundReturn`，而 `drawChart` 还把 **HS300 返回**（黄色线）和**成本线返回**（`costNavValue` 虚线）一起纳入最小/最大。当 HS300 跌得比基金深（002910 的 HS300 跌到 -29.9% 附近，基金只跌到 -10.6%），click 用的范围比 draw 小很多，`toY(fundReturn)` 映射出更低的 Y，高亮点就掉到下方了。
- 修复：点击的 `allReturns` 构造完全照搬 `drawChart`——加入 `showHS300Line` 时的 HS300 返回和 `costNavValue>0` 时的成本线返回。`vue-tsc -b` 通过。
- 教训：点击命中判定必须**逐字段**复用 `drawChart` 的坐标系（X/Y/range/padding），只复用一部分（X 和延伸点逻辑）不够；遗漏任何一个参与范围/坐标的元素都会导致高亮/命中错位。
