## 全景大屏 顶部指数分时展开功能
- 需求：全景大屏顶部 A 股指数（上证指数/沪深300/创业板指）点击展开，右侧方块显示当天完整分时曲线。
- 数据源选型（关键坑）：`web.ifzq.gtimg.cn/appstock/app/minute/query` 能返回指数分钟数据，但**无 CORS 头且忽略 callback，浏览器/WebView 无法跨域取**。最终用**东方财富 trends2 JSONP**：`https://push2his.eastmoney.com/api/qt/stock/trends2/get?secid={secid}&fields1=f1,f2,f3,f7&fields2=f51,f52,f53,f54,f55,f56,f57,f58&iscr=0&ndays=1&cb={cb}`，支持 `cb` JSONP，单请求含 时间/开/收/高/低/量/额/均价。Sina `jsonp_v2` 也能用但带 `/*location.href*/` 反爬壳，弃用。
- secid 映射：上证 000001→1.000001，沪深300 000300→1.000300，创业板 399006→0.399006（见 `INDEX_SECID_MAP`）。
- 昨收基准线：trends2 不返回 prevClose，用现有行情 `current/(1+changePercent/100)` 推算。
- 改动文件：`src/api/fundFast.ts`(新增 fetchIndexTimeShare/getIndexSecid/类型)、`src/components/IndexTimeShareChart.vue`(SVG 分时图，含午休断层、均价线、涨红跌绿、ResizeObserver 自适应；新增 compact 示意图模式，去轴标签/收紧 padding)、`src/views/PanoramaDashboard.vue`(tile 可点击 + 选中后在**该 tile 右侧内联同尺寸小方块**显示紧凑分时示意图 + 自动刷新时同步刷新分时)。
- UI 终态：点击创业板/沪深300/上证指数任一块，在其右侧紧邻插入一个与 tile 同高的小方块（min-width 110px），内嵌分时曲线（**紧凑模式：纯折线、无任何文字**）；右上角 ✕ 收起；再次点同一块也收起。不占下方空间。
- 排查「有时空白」根因：自动刷新若某次请求失败，`fetchIndexTimeShare` 返回空 points 会**覆盖已显示的好曲线**导致空白。修复：① fetchIndexTimeShare 加 15s 缓存 + 失败重试(2次/700ms) + 同 secid 并发去重；② 调用侧 `loadIndexTimeShare` 刷新时**保留旧曲线、仅非空结果才更新**，首次加载才显示 loading。刷新频率跟随全景 60s 自动刷新，不额外高频请求。
- 验证：`npx vue-tsc -b` 通过（exit 0）。未跑浏览器实测（需网络）。
- **临时停用**：东方财富分时接口数据不稳定，用户要求先关闭点击入口（代码全保留）。PanoramaDashboard 顶部加 `const INDEX_TIMESHARE_ENABLED = false`，`selectIndex` 首行 `if (!INDEX_TIMESHARE_ENABLED) return`，tile 的 `clickable/active` class 与 mini 方块 `v-if` 均加该 flag 判定。改 `true` 即可重新启用。

## arc-svg 金额显示 0 的修复（用户报「现在看到的金额都是0」）
- 根因：今天盘中的采样点是**加 a 字段之前**的旧代码记录的，所以 `a` 全部 `undefined`；收盘后 `recordIntradaySamples` 跳过采样，不会再补 `a`；而 `maxAmt/minAmt` 当时**只读 `p.a`**，没有 a 就返回 0。
- 修复：`AccountReturnCurve.vue` 新增 `base?` prop（昨日市值 = 当日市值 - 当日盈亏）。`toAmount(p)` 优先用 `p.a`，其次 `p.a` 缺失但 `base>0` 时用 `v/100 * base` 反推（v 是收益率%，基准口径一致）；两者皆无才返回 null（不计入极值）。调用侧 PanoramaDashboard 传 `:base="Math.max(0, acc.stats.marketValue - acc.stats.todayProfit)"`。这样无论采样点何时记录都能正确显示 -几千 等真实盈亏金额。
- 验证：`npx vue-tsc -b` 通过（exit 0）；dev server localhost:5174 仍在跑（200），热更生效。

## 排查：全景大屏刷新是否真的在采样收益曲线（重要发现，推翻旧记忆）
- 用户问：开着网页、关掉自动刷新去睡觉，第二天开盘能否自动采到完整账户收益曲线。
- 结论：**关掉自动刷新 = 完全不采样**（任何视图都如此）。采样(`recordAccountReturnSamples`→`recordIntradaySamples`)只在 `holdingStore.refreshEstimates()` 内触发，而它的调用方只有：Home/Portfolio/Holding 的 refreshData/动作 + `initHoldings`(仅挂载时一次)。
- **关键坑（推翻原 MEMORY「首页/全景/持仓页刷新都覆盖」）**：全景 `refreshAll()` 走的是 `loadFundData()`(useFundValuation)，**不调用 `refreshEstimates`**，所以全景的 60s 自动刷新只做实时估值、不采曲线。曲线数据来自首页/持仓页/详情在自动刷新时写入 `localStorage['intraday_return_series']` 的共享数据，全景只是读出来画。→ 全景自身并不连续采样（仅挂载时 `initHoldings` 采样一次）。
- 因此「开全景+关自动刷新」采不到；「开全景+开自动刷新」也只靠挂载那一次 + 其他视图写入的数据，自身不连续采样。
- 要做到「开着网页睡觉、次日自动有完整曲线」，必要条件：① 交易时段(9:30–15:00)有刷新在跑（拉实时估值，才能算当日盈亏采样）；② 设备不能休眠（合盖/手机锁屏会暂停 JS 定时器，彻底停采；后台标签页会被节流但通常仍 ~1次/分）。关自动刷新无法达成。
- 可行修法（待用户确认）：① 让全景 `refreshAll` 也调 `recordAccountReturnSamples()`，使全景自身连续采样；② 抽一个**独立的交易时段采样定时器**（不依赖自动刷新开关、且非交易时段不调 API，避免隔夜浪费），最贴合「开着睡觉、次日自动采集」诉求。两者都仍需设备保持唤醒。
- 补充：交易时段约 240 分钟，1点/分 → 240 点 < MAX_POINTS(320)，不会截断。
